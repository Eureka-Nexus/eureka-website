# Contributing to Eureka Nexus

Thank you for your interest in Eureka Nexus.

Eureka Nexus is currently a source-available project under active
development.

Public visibility of the repository does not mean that all project
components are open source.

## Before contributing

Please read:

- `LICENSE`
- `SECURITY.md`
- `COPYRIGHT.md`
- `NOTICE.md`
- `docs/ARCHITECTURE.md`

## Security issues

Do not publish exploitable vulnerabilities, credentials or private
infrastructure information in a public issue.

Send security-sensitive reports to:

`official@eurekanexus.pt`

See:

`SECURITY.md`

## Never submit secrets

A contribution must never contain:

- Seed phrases
- Private keys
- API keys
- Passwords
- Authentication tokens
- Relayer signing secrets
- Private RPC credentials
- `.env` files
- Keystores
- Personal identity data belonging to users

## Contributions

Potential contributions may include:

- Bug fixes
- Documentation improvements
- Accessibility improvements
- Security improvements
- Performance improvements
- Tested compatibility fixes
- Translation corrections
- Technical proposals

Acceptance is not guaranteed.

## Contributor rights

Only submit material that you created yourself or that you have the
legal right to submit.

Do not copy proprietary code or content from another project.

By intentionally submitting material for inclusion in Eureka Nexus,
you agree to the contribution terms described in the repository
`LICENSE`.

## Project decisions

Eureka Nexus may modify, reject, postpone or remove proposed
contributions based on:

- Architecture
- Security
- Product direction
- Legal considerations
- Maintenance cost
- Compatibility
- Quality
- Project priorities

## Financial and market code

Changes affecting any of the following require additional review:

- Token supply
- Mining rewards
- Pool fees
- Automatic payouts
- Market Reserve
- Launch Curve
- Treasury routing
- Liquidity
- DEX migration
- Smart contracts
- Pre-Round logic
- Payment infrastructure

Do not treat proposed financial parameters as active merely because
they appear in a branch, pull request or discussion.

Only official production releases and verified public documentation
define active project behaviour.
